# OpsHub · 内容运营管理平台

> 需求文档 v1.0 ｜ 技术栈：Vue 3 + TypeScript + Pinia + Vue Router 4 + Element Plus + Vite
> 工期：3 周（21 天）｜ 定位：**面试作品集项目**

---

## 一、为什么做这个项目

面试官看到一份南京外包的简历，"做了什么项目"是最先被问的。如果回答"做了个后台管理系统，增删改查"，
基本就结束了。

这个项目的设计原则是：**用一个中后台的壳，装进真正能拉开差距的东西。**

| 常见的外包项目 | 这个项目 |
|---|---|
| 堆页面、堆 CRUD | 提炼可复用的基础设施（3 个核心 Hook + 2 个通用组件） |
| 权限写死在代码里 | RBAC 动态路由 + 按钮级权限，后端下发菜单 |
| 表单靠复制粘贴 | Schema 驱动的动态表单引擎 |
| 性能靠"感觉不卡" | 有埋点、有指标、有优化前后对比数据 |
| 没有工程规范 | ESLint + 单测 + 构建分析 + CI |

**做完之后你简历上能写的不是"做过后台管理系统"，而是"设计并落地了一套权限体系、三个通用 Hook、
一个 Schema 驱动的表单引擎，首屏从 X 优化到 Y"。**

---

## 二、业务域

内容运营团队日常要管理平台上的内容（图文 / 视频封面），走「草稿 → 待审核 → 已发布 / 已驳回」的流程。

角色：
- **超级管理员**：全部权限
- **运营**：可创建、编辑自己负责的内容
- **审核员**：只能审核，不能编辑
- **访客**：只读

## 三、技术栈与约束

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | Vue 3.5 (`<script setup>` + TS) | 全量 TypeScript，不写 any |
| 构建 | Vite 8 | 分包、别名、代理 |
| 状态 | Pinia | user / app / permission 三个 store |
| 路由 | Vue Router 4 | 动态路由、守卫、元信息 |
| UI | Element Plus | 全量引入（内网环境，不装 unplugin） |
| 图表 | ECharts | 工作台看板 |  
| 请求 | Axios | 拦截器统一处理 token / 错误 |
| 规范 | ESLint + Prettier | Flat Config |
| 测试 | Vitest | 至少覆盖 3 个 Hook |
| 数据 | **Mock（MSW 或本地 mock 模块）** | 无后端，前端自己模拟 |

> ⚠️ 内网环境约束：**不引入任何需要额外安装的新依赖**，除上面列的之外。
> Mock 用 Vite 的 `server.proxy` + 本地 JSON，或者直接写 `src/mock/` 模块。

## 四、功能需求

### 4.1 登录鉴权

| 编号 | 功能 | 说明 |
|---|---|---|
| A-01 | 账号密码登录 | 表单校验、loading 态、错误提示 |
| A-02 | 记住登录态 | token 存 localStorage，刷新不丢 |
| A-03 | 路由守卫 | 未登录访问任意页 → 跳登录；已登录访问登录页 → 跳首页 |
| A-04 | token 失效处理 | 接口返回 401 → 清空登录态 + 跳登录 |
| A-05 | 退出登录 | 二次确认 → 清 token → 跳登录 |

**技术要点**：Pinia 持久化、`router.beforeEach`、axios 响应拦截器。

---

### 4.2 权限体系（核心模块）

| 编号 | 功能 | 说明 |
|---|---|---|
| B-01 | RBAC 模型 | 用户 → 角色 → 权限点（`content:create` / `content:audit`） |
| B-02 | 动态菜单 | 登录后按角色从 mock 接口取菜单树，前端 `router.addRoute()` 注册 |
| B-03 | 动态路由 | 未授权路由直接不存在，手动输 URL 也进不去 |
| B-04 | 按钮级权限 | `v-permission="'content:create'"`，无权限时移除元素 |
| B-05 | 权限判断 Hook | `usePermission()` 返回 `hasPerm()/hasRole()`，用于 JS 逻辑里判断 |
| B-06 | 404 兜底 | 未匹配路由跳 404 页 |

**技术要点（面试重点）**：
- `router.addRoute()` 的时机与副作用（刷新后路由丢失怎么办 → 守卫里重新注册）
- 自定义指令的生命周期（`mounted` 里移除元素）
- 权限与菜单的单一数据源设计

---

### 4.3 工作台（Dashboard）

| 编号 | 功能 | 说明 |
|---|---|---|
| C-01 | 数据卡片 | 4 个指标卡（今日新增 / 待审核 / 已发布 / 驳回率） |
| C-02 | 趋势图 | 折线图，近 7 天发布量 |
| C-03 | 分布图 | 饼图，内容分类占比 |
| C-04 | 待办列表 | 待审核内容 Top 5，点击跳转 |
| C-05 | 自适应 | 窗口 resize 时图表跟随 |

**技术要点**：`useTemplateRef` 拿 DOM → `echarts.init` → `onBeforeUnmount` 必须 `dispose()` → 窗口 resize 节流。

---

### 4.4 用户管理

| 编号 | 功能 | 说明 |
|---|---|---|
| D-01 | 列表 | 表格 + 分页 + 排序 |
| D-02 | 搜索 | 关键词（防抖 300ms）+ 状态筛选 |
| D-03 | 新增 / 编辑 | 抽屉表单，复用动态表单引擎 |
| D-04 | 删除 | 单条 + 批量（二次确认） |
| D-05 | 角色分配 | 多选角色 |
| D-06 | 导出 | 前端生成 CSV（不依赖后端） |

**技术要点**：`useTable` Hook 抽离分页/搜索/选中逻辑；防抖；批量操作的状态管理。

---

### 4.5 内容管理（业务主线）

| 编号 | 功能 | 说明 |
|---|---|---|
| E-01 | 列表 | 多条件筛选（状态 / 分类 / 时间范围） |
| E-02 | 详情 / 编辑 | **Schema 驱动的动态表单** |
| E-03 | 发布 / 驳回 | 状态流转 + 表单校验 |
| E-04 | 批量操作 | 批量发布 / 批量删除 |
| E-05 | 审核记录 | 时间轴展示操作历史 |
| E-06 | 富文本 | 可以用 textarea 降级，不强求富文本编辑器 |

**技术要点**：动态表单引擎、状态机式流转、复杂表单校验。

---

### 4.6 动态表单引擎（核心亮点）

| 编号 | 功能 | 说明 |
|---|---|---|
| F-01 | Schema 定义 | `{ field, label, type, rules, options, ... }[]` |
| F-02 | 支持控件 | input / textarea / number / select / date / switch / radio |
| F-03 | 校验规则 | 必填、长度、正则、自定义函数 |
| F-04 | 布局 | 支持单列 / 两列 |
| F-05 | 联动 | 某字段变化时控制另一字段的显隐 / 禁用 |
| F-06 | 类型安全 | 泛型组件，`v-model` 值类型由 schema 推导 |

**技术要点（这是最能体现水平的部分）**：
- 泛型组件 + `defineModel`
- 动态组件 `<component :is>`
- Schema 到 FormItem 的映射表设计
- 值类型推导（`InferFormValue<T>`）

## 五、非功能需求

### 5.1 性能指标

| 指标 | 目标 | 怎么测 |
|---|---|---|
| 首屏加载 | < 1.5s（本地） | `performance.timing` 或埋点面板 |
| 路由切换 | < 300ms | 自制埋点 |
| 大表格渲染 | 10000 行不卡（用虚拟列表或分页） | 手动构造数据实测 |
| 首屏 JS 体积 | < 400KB（gzip 前） | `rollup-plugin-visualizer` 或 `vite build --report` |

> **重要**：每个指标都要记录 **优化前 / 优化后** 的数字。这是简历上最有价值的内容。

### 5.2 工程质量

- `pnpm build` 零错误零警告
- `pnpm lint` 零 error
- 至少 3 个 Hook 有单测（`useRequest` / `useTable` / `usePermission`）
- 全部组件使用 `<script setup lang="ts">`，不出现 `any`（`eslint-disable` 除外且要有注释）

### 5.3 可访问性 / 体验

- 所有按钮有 hover / disabled 态
- 表单错误提示定位到具体字段
- 加载态用骨架屏而非白屏
- 删除类操作必须二次确认
